## 2. 与源码不一致的项（必须修正）

### 2.1 认证 API 路径错误（4.1 节）

| 文档写的 | 源码实际 | 说明 |
|---|---|---|
| `POST /api/v1/auth/refresh` | `POST /api/v1/auth/token/refresh` | 路径前缀多了 `token/` |
| `GET /api/v1/auth/userinfo` | `GET /api/v1/auth/me` | 路径名不一致；视图函数虽叫 `userinfo`，但 URL 是 `/me` |
| `PUT /api/v1/auth/userinfo` | `PUT /api/v1/auth/me` | 同上 |
| `PATCH /api/v1/auth/userinfo/password` | `PATCH /api/v1/auth/me/password` | 同上 |

**缺失的认证接口**（源码存在但文档 4.1 未列）：

- `POST /api/v1/auth/sms/verify`（短信验证码校验）
- `POST /api/v1/auth/sms/send/pwd`（发送改密验证码）
- `POST /api/v1/auth/wechat/login`（微信小程序登录）
- `POST /api/v1/auth/me/password/reset`（短信重置密码）
- `GET /api/v1/auth/me/profile`（获取用户资料）
- `PUT /api/v1/auth/me/profile`（更新用户资料）

> 注：[README.md](file:///e:/framework/Unified%20account%20identification%20service/README.md) 的 API 概览表与源码一致，设计文档 v1.5 反而是过时版本。

### 2.2 开放 API 遗漏（4.2 节）

文档列出 7 个开放 API，源码实际还提供：

- `GET /api/v1/open/user/profile/by_token` — 通过 Token 获取用户资料，权限码 `user:profile:read`
- `PUT /api/v1/open/user/profile/by_token` — 通过 Token 修改用户资料，权限码 `user:profile:update`
- `GET /api/v1/open/wechat/access_token` — 获取微信 AccessToken（自动缓存），权限码 `wechat:access_token`
- `POST /api/v1/open/wechat/get_phone_number` — 获取微信用户手机号，权限码 `wechat:phone`

权限码数量从 5 个增至 9 个（v1.5 的 5.14 节只列了 5 个预置权限）。

## 3. 源码存在但文档未提及的功能（补充）

### 3.1 管理后台新增接口（4.3 节遗漏）

按用途分类：

| 类别 | 接口 | 功能 |
|---|---|---|
| 登录 | `POST /api/v1/admin/login` | 管理后台独立登录（与 `/api/v1/auth/login` 区分） |
| 登录 | `POST /api/v1/admin/login-test` | 登录测试页专用 |
| 用户批量 | `POST /api/v1/admin/users/batch-status` | 批量启用/禁用 |
| 用户批量 | `POST /api/v1/admin/users/batch-user-type` | 批量切换内部/外部用户 |
| 用户批量 | `POST /api/v1/admin/users/batch-delete` | 批量删除 |
| 用户导入导出 | `GET /api/v1/admin/users/export` | 导出用户 |
| 用户导入导出 | `POST /api/v1/admin/users/import` | 导入用户 |
| 用户资料 | `GET/PUT /api/v1/admin/users/<id>/profile` | 用户资料读写 |
| 用户标签 | `GET/PUT /api/v1/admin/users/<id>/tags` | 用户标签绑定 |
| 应用密钥 | `GET /api/v1/admin/applications/<id>/secret` | 查看应用密钥（脱敏） |
| 应用角色 | `GET/PUT /api/v1/admin/applications/<id>/roles` | 应用可使用的角色范围 |
| 角色复制 | `POST /api/v1/admin/roles/<id>/copy` | 复制角色（文档 P1 表已提，但 4.3 清单未列） |
| 部门管理 | `GET/POST /api/v1/admin/departments` | 部门列表/创建 |
| 部门管理 | `GET/PUT/DELETE /api/v1/admin/departments/<id>` | 部门详情/编辑/删除 |
| 审计日志导出 | `GET /api/v1/admin/audit-logs/export` | 导出审计日志 |
| 短信测试 | `POST /api/v1/admin/tenant-sms-config/test` | 短信渠道连通性测试 |
| 标签管理 | `GET /api/v1/admin/tags` 等 5 个 | 完整的标签 CRUD + 用户绑定/解绑 |

- `POST /api/v1/superadmin/tenants/<id>` — 源码中该路径同时接受 POST（部分版本兼容性写法）

## 5. 菜单/导航命名差异

| 文档说法 | 源码实际菜单（前端侧边栏） |
|---|---|
| 企业管理员"仪表盘" | 「工作台」（`/admin-panel/dashboard/`） |
| 超管"平台总览"/"全局概览" | 「全局概览」（`/admin-panel/superadmin/dashboard/`） |
| "角色权限"（合并页） | 实际为「角色管理」；权限仅以弹窗形式嵌入角色/应用编辑，无独立菜单 |
| "审计日志" | 一致（租户侧叫「审计日志」，超管侧叫「全局审计」） |
| "统计报表" | 一致（仅超管侧） |
| "API 统计" | 一致（仅超管侧，独立菜单） |
| "全局配置" | 前端叫「平台配置」 |
| — | 源码额外有「部门管理」「标签管理」「登录测试」三个租户侧菜单，文档未单列 |

**菜单分组逻辑**：纯超管只看到「平台管理」分组；租户管理员/模拟中的超管只看到「租户管理」分组。文档 5.1.4 节"模拟模式下隐藏超管专属菜单"的描述与实现一致。

## 6. 文档结构建议

1. **4.1 节需要重写**：把路径全部改成与源码一致（`/token/refresh`、`/me` 系列），并补全 6 个遗漏接口。
2. **4.2 节**：补 4 个微信/资料类开放接口和对应的权限码。
3. **4.3 节**：补全批量、导入导出、部门、标签、应用密钥/角色等约 20 个接口。
4. **4.4 节**：补 `audit-logs/export` 和 `report/endpoint-stats`。
5. **5.14 节预置权限表**：从 5 个扩到 9 个（新增 `user:profile:read`、`user:profile:update`、`wechat:access_token`、`wechat:phone`）。
6. **前端菜单名称**：统一为"工作台/全局概览/平台配置"的实际命名，新增"部门管理/标签管理/登录测试"条目。
7. 本文档归档到 `document/archive/`，原始 v1.5 文档保留在 `document/` 根目录，待下一轮修订时升为 v1.6。
