## 1. 角色与登录

### 1.1 角色识别

| 角色 | 判定依据 | 进入后台后看到的菜单 |
|---|---|---|
| **超级管理员**（平台运营） | `User.is_superuser=True` 或 `User.is_superadmin=True` | 仅「平台管理」分组 |
| **企业管理员**（租户管理员） | `User.is_staff=True` 且属于某租户 | 仅「租户管理」分组 |
| **模拟模式中的超管** | Token 中 `impersonated=True` | 临时切到「租户管理」分组，顶部显示醒目"模拟模式"条 |

> 同一账号在同一时间只会看到一个分组，前端按 `buildMenus(user)` 自动过滤。

### 1.2 登录入口

- **后台登录页**：浏览器访问 `<域名>/admin-panel/login/`
- 登录成功后根据角色自动跳转：
  - 超管 → `/admin-panel/superadmin/dashboard/`
  - 租户管理员 → `/admin-panel/dashboard/`
- 后端登录接口：`POST /api/v1/admin/login`（与面向 App 的 `/api/v1/auth/login` 不同）

### 1.3 Token 说明

- 管理后台登录成功后，前端会拿到 Access Token（2 小时有效）和 Refresh Token（30 天有效）
- 所有 `/api/v1/admin/*`、`/api/v1/superadmin/*` 请求都要在 Header 携带 `Authorization: Bearer <access_token>`
- 过期后前端自动调用 `POST /api/v1/auth/token/refresh` 用 Refresh Token 换新 Access Token

## 2. 企业管理员（租户管理员）操作

进入后台后默认显示「工作台」。左侧菜单共 9 项：

### 2.1 工作台（`/admin-panel/dashboard/`）

进入后看到：

- **顶部 6 张统计卡片**：用户总数、活跃用户、今日新增、应用总数、活跃应用、角色总数
- **登录趋势 Mini 折线图**：最近 7 天登录次数
- **用户类型分布**：内部/外部用户占比
- **应用统计表**：每个应用的名称、AppKey（脱敏）、状态、近 7 天调用次数、创建时间
- **最近操作动态**：最新 10 条审计日志

**操作说明**：只读页面，无编辑按钮。数据来自 `GET /api/v1/admin/stats`。

### 2.2 用户管理（`/admin-panel/users/`）

**页面能力**：

| 操作 | 位置 | 备注 |
|---|---|---|
| 搜索 | 顶部搜索框 | 按用户名/昵称/手机号模糊搜索 |
| 筛选 | 顶部筛选栏 | 用户类型（内部/外部）、状态（启用/禁用）、所属部门 |
| 新增用户 | 右上"新增"按钮 | 弹窗填表，含用户名、密码、姓名、手机、邮箱、部门下拉、角色多选 |
| 编辑用户 | 行内"编辑"按钮 | 同上弹窗，预填数据 |
| 启用/禁用 | 行内开关 | 调用 `PATCH /users/<id>/status` |
| 重置密码 | 行内"更多 → 重置密码" | 管理员直接指定新密码，无需原密码 |
| 分配角色 | 编辑弹窗"角色分配"区 | 多选，保存后写入 `PUT /users/<id>/roles` |
| 分配部门 | 编辑弹窗"部门"下拉 | 从组织架构树选择 |
| 分配标签 | 编辑弹窗"标签"区 | 可多选标签 |
| 批量操作 | 勾选行后顶部出现批量栏 | 批量启用/禁用、批量切换内部/外部、批量删除 |
| 导入/导出 | 顶部"导入/导出"按钮 | 导出 CSV；导入支持模板下载 |

**接口参考**：`GET/POST /api/v1/admin/users`、`GET/PUT/DELETE /api/v1/admin/users/<id>`、`POST /users/<id>/reset-password`、`GET/PUT /users/<id>/roles`、`GET/PUT /users/<id>/profile`、`GET/PUT /users/<id>/tags`。

### 2.3 应用管理（`/admin-panel/applications/`）

| 操作 | 位置 | 备注 |
|---|---|---|
| 应用列表 | 主表格 | 显示应用名称、AppKey、状态、近 7 天调用次数 |
| 新增应用 | 右上"新增"按钮 | 填写应用名、回调地址 |
| 编辑应用 | 行内"编辑" | 弹窗内含两个折叠区：**基本信息** + **微信登录配置**（小程序 AppID/Secret、网页 AppID/Secret） |
| 启用/禁用应用 | 行内开关 | |
| 重新生成密钥 | 行内"更多 → 重新生成 Secret" | 二次确认；旧 Secret 立即失效 |
| 查看密钥 | 行内"查看 Secret" | 显示为 `***`，点"显示"按钮才明文 |
| 配置应用权限 | 编辑弹窗"权限"Tab | 从权限列表勾选开放 API 权限码 |
| 配置可用角色 | 编辑弹窗"角色"Tab | 限定该应用下用户可分配的角色范围 |
| API 调用统计 | 行内"API 统计"按钮 | 弹窗显示该应用近 N 天每日调用趋势 + 各接口排行 |

**微信配置注意事项**：
- 小程序与网页是两套独立的 AppID/Secret，互相不通用
- Secret 字段默认显示为 `***`，留空保存表示不修改；填新值才会覆盖
- 未配置微信的应用在社交登录时走 Mock 模式（用于本地测试）

### 2.4 角色管理（`/admin-panel/roles/`）

| 操作 | 位置 |
|---|---|
| 角色列表 | 显示角色名、编码、描述、权限标签 |
| 新增角色 | 右上按钮，含名称、编码、描述、权限勾选（按分类分组，中文名称+中文描述） |
| 编辑角色 | 行内按钮 |
| 复制角色 | 行内"更多 → 复制" |
| 删除角色 | 行内"更多 → 删除"（已有用户绑定的角色禁止删除） |

**权限显示**：权限标签直接显示中文（如"创建用户"），鼠标悬停显示详细描述。

### 2.5 部门管理（`/admin-panel/departments/`）

树形组织架构页面。

- 左侧为部门树，右侧为选中部门的子部门列表和该部门下的用户
- 支持新增根部门、新增子部门、编辑、删除（有用户或子部门的部门禁止删除）
- 部门创建后会生成唯一 `code`，供开放 API 中 `dept_code` 字段使用

### 2.6 标签管理（`/admin-panel/tags/`）

简单标签 CRUD：新增、编辑、删除。用户标签绑定在用户管理页完成。

### 2.7 审计日志（`/admin-panel/audit/`）

| 操作 | 位置 | 备注 |
|---|---|---|
| 日志列表 | 主表格 | 时间、操作人、动作、IP、结果 |
| 筛选 | 顶部 | 按操作人、动作、时间范围、成功/失败 |
| 详情 | 行内"详情" | 弹窗展示请求参数与响应；如果是模拟操作会显示"模拟操作"标识和原操作人 |
| 导出 | 右上"导出" | 按当前筛选条件导出 CSV |

### 2.8 短信配置（`/admin-panel/sms-config/`）

租户自定义短信渠道。

| 字段 | 说明 |
|---|---|
| 服务商 | 下拉选择 `mock`（测试）或 `aliyun`（阿里云） |
| AccessKey ID | 阿里云控制台获取 |
| AccessKey Secret | 显示为 `***`，留空保存表示不修改 |
| 短信签名 | 已在阿里云备案的签名 |
| 模板编码 | 已审核通过的模板 CODE |

**保存后建议点"发送测试短信"**：系统会向当前登录管理员的手机发一条验证码，验证配置是否正确。

**回退规则**：如果租户未配置（`sms_provider` 为空），系统自动回退到平台全局短信配置。

### 2.9 登录测试（`/admin-panel/login-test/`）

面向开发/测试人员的工具页，模拟客户端发起：密码登录、发短信验证码、短信登录、社交登录等请求，用于联调。

## 3. 超级管理员（平台运营）操作

纯超管登录后默认显示「全局概览」。左侧菜单共 6 项：

### 3.1 全局概览（`/admin-panel/superadmin/dashboard/`）

- **全局统计卡片**：租户总数、活跃租户、总用户数、活跃用户、总应用数、活跃应用、角色总数
- **租户增长 Mini 图**：近 7 天新增租户数
- **活跃租户 Top 5**：按近 30 天活跃用户数排名
- **应用调用 Top 5**：按调用次数排名
- **租户概览表格**：租户名称、标识、状态、用户数、应用数、创建时间

数据接口：`GET /api/v1/superadmin/global-stats`。

### 3.2 租户管理（`/admin-panel/superadmin/tenants/`）

| 操作 | 位置 | 备注 |
|---|---|---|
| 租户列表 | 主表格 | 名称、标识、状态、用户数、应用数、创建时间 |
| 搜索/筛选 | 顶部 | 按名称/标识模糊搜索，按状态筛选 |
| 新增租户 | 右上按钮 | 填写名称、唯一标识（slug） |
| 编辑租户 | 行内按钮 | 可改名称、状态（启用/禁用） |
| 模拟进入 | 行内"模拟"按钮 | **进入该租户的企业管理员视角**，见 3.3 |
| 删除租户 | 行内"更多 → 删除" | 二次确认；已有关联用户/应用的租户禁止直接删除，需先禁用 |

### 3.3 模拟租户模式

**进入**：租户列表点击"模拟"按钮后，前端切换到租户管理分组，顶部出现醒目橙色条：

> "当前为模拟模式，正在模拟租户：XX科技  [退出模拟]"

**可进行的操作**：与普通租户管理员完全一致（工作台/用户/应用/角色/部门/标签/审计/短信配置）。

**不可进行的操作**：所有 `/api/v1/superadmin/*` 平台级接口（除 `impersonate/exit` 外）一律 403。

**退出**：
- 点顶部"退出模拟"按钮 → 调 `POST /api/v1/superadmin/impersonate/exit` → 回到全局概览
- 所有模拟操作都会在审计日志中标记 `is_impersonated=true` 和 `impersonated_by=<超管账号>`

> **安全提示**：模拟模式下执行的增删改操作会真实写入租户数据，请谨慎操作。

### 3.4 全局审计（`/admin-panel/superadmin/audit/`）

跨租户的审计日志，筛选和详情页面与租户侧审计日志一致，额外支持按租户筛选。支持导出 CSV。

### 3.5 统计报表（`/admin-panel/superadmin/report/`）

页面顶部有 3 个 Tab：

**Tab 1：租户报表**
- 工具栏：关键词搜索 + 创建日期范围 + 排序
- 表格列：名称、标识、状态、用户数、近 30 天活跃用户、应用数、API 调用总数、创建时间
- 行内按钮："查看接口" → 弹窗展示该租户所有接口的调用明细

**Tab 2：应用报表**
- 工具栏：关键词 + 所属租户筛选 + 日期范围 + 排序
- 表格列：应用名、AppKey（脱敏）、状态、所属租户、调用次数、创建时间
- 行内按钮："查看接口" → 弹窗展示该应用所有接口的调用明细

**Tab 3：接口统计**
- 工具栏：接口类型（全部/应用接口/管理接口）+ 租户 ID + 应用 ID + 日期范围
- 表格列：API 路径、调用次数、来源（应用接口/管理接口）、所属应用或租户

接口：`POST /api/v1/superadmin/report/tenants`、`POST /report/apps`、`POST /report/endpoint-stats`。

### 3.6 API 统计（`/admin-panel/superadmin/api-stats/`）

独立的 API 调用趋势页面，按日期维度展示全平台应用调用总量曲线和 Top 应用排行。接口：`GET /api/v1/superadmin/api-stats?days=N`。

### 3.7 平台配置（`/admin-panel/superadmin/config/`）

**只读**的全局配置展示页，分类卡片：

- 邮件服务（SMTP 主机/端口/账号/发件人）
- 短信服务（全局默认短信渠道）
- 社交登录（微信/钉钉/飞书 AppID 与 Secret）
- 安全策略（密码最小长度、是否含数字/大写、账号锁定阈值）
- Token 策略（Access 有效期、Refresh 有效期）
- 限流配置（IP 级、AppKey 级默认阈值）

敏感字段一律显示 `***`，页面上**无编辑按钮**。如需修改请联系运维在服务器环境变量中调整后重启服务。

## 4. 常见操作场景

### 4.1 新增一个企业客户（租户）并开通使用

1. 超管 → 租户管理 → 新增租户：填写名称和唯一 slug
2. 在该租户下新增应用（可通过模拟模式进入该租户的管理员视角操作，也可以让租户管理员自行登录后创建）
3. 把 AppKey/AppSecret 提供给客户对接
4. 如需自定义短信/微信登录参数，让租户管理员在"短信配置"和应用编辑弹窗中自行填写

### 4.2 用户离职禁用

1. 租户管理员 → 用户管理 → 找到该用户 → 行内开关切到"禁用"
2. 禁用后该用户 Token 立即失效，无法登录
3. 不需要删除账号（保留审计追溯）；如确认要删除，用批量删除功能

### 4.3 应用密钥泄露应急

1. 租户管理员 → 应用管理 → 找到该应用 → 更多 → 重新生成 Secret
2. 旧 Secret 立即失效，所有用旧 Secret 签名的请求返回 401
3. 把新 Secret 通过线下渠道安全地提供给应用开发方
4. 在审计日志中可追踪到密钥被重新生成的记录

### 4.4 排查某用户登录失败

1. 租户管理员 → 审计日志 → 筛选操作人 = 该用户 + 结果 = 失败
2. 查看详情中的错误原因（密码错误 / 账号锁定 / IP 限流等）
3. 如果是账号锁定，在用户列表编辑中可手动解锁

### 4.5 超管协助排查某租户问题

1. 超管 → 租户管理 → 找到目标租户 → 点"模拟"
2. 进入租户视角查看用户、应用、日志
3. 排查完后顶部橙色条点"退出模拟"
4. 所有排查中执行的修改操作都会带模拟标识写入审计
